# P3 會後重轉錄（Breeze-ASR-25）— 組員指南

> 🟢 **活文件**。這份是「拉到這個分支後，每個人要做什麼」的分工說明。
> 功能細節見 `docs/13-系統現況與路線圖.md` 第 8 節；服務安裝細節見 `whisper-service/README.md`。

## 這個功能在做什麼（30 秒版）

會議結束、第一輪摘要生成後，後端會自動抓 Recall 的錄音檔，交給
**whisper-service**（跑 MediaTek Breeze-ASR-25 模型，台灣中文優化、原生繁體）
重新轉一份高品質逐字稿（`transcript-v2.md`），再重跑一次 Dify 摘要覆寫結果。

- **預設關閉**：`backend/.env` 沒設 `WHISPER_SERVICE_URL` 就完全不啟動，一切照舊。
- whisper-service 是獨立 Python 服務，**全組只需要一台機器跑它**（建議有 NVIDIA GPU 的桌機），
  其他人的後端透過區網連過去。

## A. 跑 whisper-service 的組員（有 NVIDIA GPU 的桌機）

> 完整步驟在 `whisper-service/README.md`，這裡是摘要。

1. **需求**：Python 3.10+、ffmpeg（`winget install Gyan.FFmpeg`，裝完重開終端機）
2. **安裝**（首次）：
   ```bash
   cd whisper-service
   python -m venv .venv
   .venv\Scripts\activate
   pip install torch --index-url https://download.pytorch.org/whl/cu124   # CUDA 12.x
   pip install -r requirements.txt
   ```
3. **啟動**：
   ```bash
   uvicorn main:app --host 0.0.0.0 --port 8200
   ```
   - 首次轉錄會自動下載 ~3GB 模型（之後走快取），第一件 job 會比較久。
4. **開防火牆**：Windows 防火牆放行 TCP 8200（入站），否則區網其他機器連不到。
5. **確認 GPU 有吃到**：`curl http://localhost:8200/health` → `"device":"cuda"` 才對；
   顯示 `cpu` 代表 torch 裝到 CPU 版，回到步驟 2 重裝 CUDA 版 torch。
6. **把你的區網 IP 告訴大家**（`ipconfig` 看 IPv4），例如 `192.168.1.50`。

> 沒有 GPU 也能跑（CPU 模式），只是慢：一小時會議約要轉 20–40 分鐘。
> 流程是非同步的，慢不會卡住任何人的後端。

## B. 其他組員（不需要裝 Python）

拉到這個分支後：

1. **更新依賴與 Prisma client**（schema 有新欄位，不重新 generate 後端起不來）：
   ```bash
   cd backend
   npm install
   npx prisma generate
   ```
   > 不需要跑 `prisma db push`——共用的 Supabase DB 已經推過了。
   > 若 generate 報 EPERM：先關掉正在跑的後端 dev server 再執行。
2. **要測這個功能的人**：在 `backend/.env` 加一行（IP 換成 A 組員給的）：
   ```env
   WHISPER_SERVICE_URL="http://192.168.1.50:8200"
   ```
3. **重啟後端**：`npm run dev`。啟動 log 看到 `Retranscription poller started` 即生效。

## C. 不測這功能的人

只做 B 的第 1、3 步（npm install + prisma generate + 重啟）。
**不要設 `WHISPER_SERVICE_URL`**，功能整體關閉，所有既有功能照舊。

## 怎麼驗證有動起來

1. 開一場真實 Recall 會議，講幾句話，結束會議。
2. 等第一輪摘要出現（前端會議頁）。
3. 看 `backend/logs/backend.log` 的 `Retranscription:` 行，狀態流：
   `whisper job submitted` → （等數分鐘，CPU 更久）→ `v2 transcript + summary completed`。
4. 前端**重新整理**會議頁 → 摘要已換成 v2 版本（覆寫後不會自動刷新，是已知行為）。
5. Storage（MinIO console 或 Supabase）`transcripts/{會議id}/` 下可比對
   `transcript.md`（Recall 原版）與 `transcript-v2.md`（Breeze 重轉版）。

## 常見問題

| 症狀 | 原因／處理 |
|------|-----------|
| log 一直沒有 `Retranscription:` 行 | `WHISPER_SERVICE_URL` 沒設（poller 未註冊），或會議還沒出第一輪摘要 |
| 卡在 PENDING、attempts 一直加 | whisper-service 沒起／防火牆擋 8200／IP 打錯。先 `curl http://<IP>:8200/health` |
| DB `retranscription_status = SKIPPED` | 正常：Vexa 會議、無錄音、或 whisper 轉出來是空的 |
| DB `retranscription_status = FAILED` | 重試 1 小時耗盡，`retranscription_error` 欄位有原因；修好後把該筆改回 `PENDING` 即會重跑 |
| 重轉錄的逐字稿沒有人名 | 已知取捨：Whisper 無說話者分離，一律顯示「參與者」（聊天訊息仍有名字）；speaker 對齊在 Backlog |
| whisper-service 機器重開機 | job 會蒸發，後端收 404 自動重送，不用人工處理 |
