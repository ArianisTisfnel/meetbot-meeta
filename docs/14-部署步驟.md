## Step 3 — `.env` 補 `DIRECT_URL`（Prisma CLI 專用連線）

PR #4 在 `schema.prisma` 加了 `directUrl = env("DIRECT_URL")`，**沒有這個變數，
任何 Prisma CLI 指令（db push / db pull / migrate）都會直接報錯**。

推導規則：拿現有 `DATABASE_URL`，做兩件事——

1. port `6543` → `5432`（transaction pooler → session pooler）
2. 去掉 `?pgbouncer=true` 等所有查詢參數

在 `backend/.env` 加一行：

```env
# Prisma CLI（db push / migrate / db pull）DDL 專用：走 5432 session pooler
# （6543 transaction pooler 跑 DDL 會被 pgbouncer 斷線，錯誤碼 P1017）
DIRECT_URL="postgresql://postgres.[PROJ]:[密碼]@aws-1-ap-southeast-1.pooler.supabase.com:5432/postgres"
```

App 執行期照舊走 `DATABASE_URL`（6543）不變；CLI 會自動選 `DIRECT_URL`，不用手動切換。


## Step 5 — 啟動後端驗證

```powershell
cd backend
npm run dev
```

⚠️ **必須用 `npm run dev`**（script 是 `tsx --env-file .env src/index.ts`）。
直接 `npx tsx src/index.ts` 不會載入 `.env`，會立刻噴
`Invalid environment variables`＋一長串 Required——這不是變數真的缺，是沒帶 `--env-file`。

預期 log（依序）：

```
botProvider: BOT_PRIMARY_PROVIDER=recall 但 RECALL_API_URL/KEY 未設定，退回 Vexa only  ← 尚未填 Recall 金鑰時的正常警告
botProvider: failover chain configured  {"primary":"vexa","secondary":null}
Indexing poller started (status: 30s, content cards: 60s)
startup restore completed
meetbot backend started on port 4000
```

填好 Recall 金鑰後重啟，第一行警告消失、chain 變成 `{"primary":"recall","secondary":"vexa"}`。

## Step 6 — Recall 區段（要測 failover / 即時問答才需要）

沒填也能跑（上一步的「退回 Vexa only」就是這個狀態），但 **Vexa 進場目前被 Google
reCAPTCHA 擋死**（詳見 13 文件），所以實際要派 bot 就得把 Recall 填起來。

⚠️ 以下變數**全部填在 `backend/.env`**，不是 `frontend/.env.local`——後端靠
`npm run dev` 的 `--env-file backend/.env` 載入，填錯檔案後端讀不到；
金鑰放前端還有被 next 打包進瀏覽器的風險（`NEXT_PUBLIC_` 開頭者必洩）。
`frontend/.env.local` 只放 NextAuth / Google OAuth / `NEXT_PUBLIC_API_URL` 那幾個（見 13 文件 7-6）。

| 變數 | 來源 |
|------|------|
| `RECALL_API_URL` / `RECALL_API_KEY` | 開發者各自上網站註冊帳號並申請 |
| `OPENAI_API_KEY` | 語音回答的 TTS；不填則只能聊天文字回答 |
| `RECALL_WEBHOOK_URL` / `RECALL_WEBHOOK_TOKEN` | 每人自己的 ngrok 固定網域＋自訂隨機字串 |

ngrok 申請與綁定步驟照 [13 文件第三節](13-Recall-Failover-開發設定.md)做（每個開發者各自一次）。

## 常見錯誤對照（本次實跑踩過/驗證過）

| 症狀 | 原因與解法 |
|------|-----------|
| 啟動即噴 `Invalid environment variables`（一長串 Required） | 用了 `npx tsx src/index.ts`；改用 `npm run dev`（要 `--env-file .env`） |
| Prisma CLI 報 `Environment variable not found: DIRECT_URL` | Step 3 沒做 |
| Prisma CLI 報 P1017（connection closed） | `DIRECT_URL` 填成 6543 了；必須是 5432 且無查詢參數 |
| 執行期 `P2021/P2022`（table/column 不存在） | 漏跑 Step 4 的 `db push` |
| log 出現 `退回 Vexa only` | Recall 金鑰未設**或填錯檔案**（要在 `backend/.env`，不是 `frontend/.env.local`）；要測 Recall 就做 Step 6，否則屬正常降級 |
| Recall API 回 401 | 金鑰與 region 不符：`RECALL_API_URL` 的網域（如 `ap-northeast-1`）要跟你申請金鑰的 dashboard region 一致 |
| 喚醒詞沒反應 / 蜜塔不說話 | 見 13 文件「除錯對照」（webhook / ngrok / OPENAI_API_KEY） |

## 正式環境（非本機）差異

- 後端有固定公開網址後，`RECALL_WEBHOOK_URL` 直接填該網址，**不需要 ngrok**。
- Bot session 狀態全在記憶體：**單進程部署**（PM2 fork mode），不可多 instance。
- 已知限制：後端重啟後無法復原跑在 Recall 上的會議 session（v1 限制，見 13 文件）。
