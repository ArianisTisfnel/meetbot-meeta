## 2. ⚠️ 要檢查:`GEMINI_INTERJECTION_API_KEY`(照過 17 文件的人一定要看)

[17-語音延遲環境安裝教學.md](17-語音延遲環境安裝教學.md) 第 5 節建議設這把 key 來隔離插話的額度。
**照做過的人,你的插話/破冰在這次合併前是全部失效的**,而且症狀只是「蜜塔忽然安靜了」。

原因:`llm.ts` 原本無條件送 `thinkingConfig: { thinkingBudget: 0 }`。

- Gemini **2.5** 系列**必須**送——不關掉,思考 token 會吃光 `maxOutputTokens` 導致空回覆
- Gemini **3.x** 直接以 HTTP 400 `Request contains an invalid argument` 拒收,而且 3.x 預設就不思考,根本不需要關

而 `GEMINI_INTERJECTION_MODEL` 的預設值正是 3.x 的 `gemini-flash-lite-latest`,
且 `llm.ts` 是「用 interjection key 就同時換 interjection model」。所以**只要這把 key 有值**,
插話決策、沉默破冰、本次新增的定址裁決會同時全部 400 陣亡,錯誤只寫在 warn log 裡。

### 你要做的事

打開 `backend/.env` 看這一行:

```env
GEMINI_INTERJECTION_API_KEY="..."
```

| 你的狀況 | 合併前的實際行為 | 合併後 |
|---------|---------------|--------|
| 有填 key | 插話/破冰**全部 400 失敗**,蜜塔只是安靜,不會報錯給你 | 自動修好,不用改 `.env` |
| 沒這行,或設了留空 | 走 `GEMINI_API_KEY` + `gemini-2.5-flash`,一切正常 | 不變 |

**兩種情況都不需要改 `.env`**,本次修正是依模型世代自動分流(已加單元測試鎖住)。
列出來是因為:如果你之前覺得「插話功能好像從來沒動過」,這就是原因,不是你設錯。

> 額度提醒:Gemini 免費層額度是綁 **Google Cloud 專案**,不是綁 key。
> 同一專案底下的多把 key 共用配額,換 key 拿不到新額度——要換就要換到不同專案的 key。

## 3. `backend/.env` 可以加的變數(選填)

```env
# 回覆功能標籤:蜜塔的聊天室訊息前加【資料檢索】【冷場插話】等功能標籤
REPLY_TAGS=on
```

- **不加也對**:程式預設就是 `on`,那正是要驗收的行為。
- 只有在測驗收清單 1-5(關掉標籤)、或開對外正式會議不想露出除錯資訊時,才需要設 `off`。
- **語音永遠不唸標籤**,不受這個開關影響。
- 完整說明見 [14-環境變數設定說明.md](14-環境變數設定說明.md) 的 1-7b 節。

改完 `.env` 要重啟後端才生效。

## 6. 兩個「看起來像 bug 但其實是設計」的行為

避免誤報,先講在前面:

1. **定址裁決失敗時她會照常回答,而不是沉默。**
   Gemini 429 時退回舊行為是刻意的——若把「呼叫失敗」當成「沒在叫我」,
   額度一枯竭蜜塔就對所有非逗號句型全聾,比偶爾多嘴嚴重得多。

2. **以「蜜塔」開頭的談論句會先 ack、然後沒有下文。**
   例如「蜜塔這個功能是不是很難做?」會先聽到「好的,我收到了,請稍候。」然後沒答案。
   partial 片段還沒加標點,無法判斷是呼喚還是談論,所以先 ack;定稿後裁決判定為
   「在談論蜜塔」,於是不回答。**只有孤兒 ack、沒有實際答案 = 正常。**

## 8. 正式部署(非本機)注意

本次沒有新增部署層面的要求。既有限制不變:

- Bot session 與講者時間軸狀態都在記憶體,維持**單進程部署**(PM2 fork mode),不可多 instance。
- `REPLY_TAGS` 建議在對外正式場合設 `off`,避免除錯標籤出現在客戶眼前。
