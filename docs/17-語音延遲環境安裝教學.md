## 0. 這份教學在裝什麼

蜜塔原本「喊了名字要等幾十秒到幾分鐘才回應」,根因是 Recall 的中文轉錄模式
(`prioritize_accuracy`)本質是批次處理,文字晚到,後面全部被拖著等。

修正方案(方案 A)改成:**bot 掛一個 agent 網頁當耳朵和嘴巴**——
網頁直接收會議音訊、串流送回後端做即時轉錄(OpenAI `gpt-4o-mini-transcribe`)、
喚醒後用串流 TTS 邊合成邊播。目標:說「蜜塔」→ 聽到「我收到了」**< 1.5 秒**。

要讓這條路在你的電腦上通,除了原本的基本環境,還需要:

| 需要什麼 | 為什麼 |
|---------|--------|
| Recall API key(每人自己申請) | 派 bot 進會議 |
| OpenAI API key | agent 模式的即時轉錄(STT)+ 語音合成(TTS) |
| ngrok(帳號 + 固定網域) | Recall webhook 要能 POST 到你本機的後端 |
| cloudflared | bot 的雲端瀏覽器要能開到你本機的 agent 網頁 |
| `backend/.env` 幾個新變數 | 見第 3 節 |

## 2. 安裝兩條 tunnel 工具

本機的 4000 port 外網進不來,但有兩個東西必須從外面連進來:

1. **Recall webhook**(即時逐字稿/聊天訊息)→ 用 **ngrok**
2. **agent 網頁**(bot 的雲端瀏覽器要開它)→ 用 **cloudflared**

> 為什麼要兩套?ngrok 免費網域對「瀏覽器導覽」會插 ERR_NGROK_6024 警告頁,
> bot 開不進 agent 網頁,所以 agent 網頁只能走 cloudflared;
> 而 webhook 需要固定網址(寫死在 .env),cloudflared quick tunnel 網址每次都變,
> 所以 webhook 繼續用 ngrok 固定網域。各管各的。

### 2-1. ngrok(每人做一次)

1. 到 [ngrok.com](https://ngrok.com) 註冊免費帳號
2. 下載 ngrok.exe(放專案的 `tools\ngrok.exe`,或裝到 PATH 上都可以,`start.ps1` 兩處都會找)
3. 綁 authtoken:`ngrok config add-authtoken <你的token>`(dashboard 首頁有)
4. 到 dashboard → **Domains** → 領你的免費固定網域(長得像 `xxx-yyy.ngrok-free.dev`)

### 2-2. cloudflared(每人做一次)

```powershell
winget install Cloudflare.cloudflared
```

裝完**開一個新的 PowerShell** 確認 `cloudflared --version` 有輸出。
(不用註冊帳號、不用設定,`start.ps1` 會自動開 quick tunnel。)

## 3. `backend/.env` 設定

> ⚠️ 以下**全部填在 `backend/.env`**,不是 `frontend/.env.local`。
> ⚠️ **改完 .env 一定要重啟後端才生效**(dev 模式沒有 watch)。
> 完整變數說明見 [14-環境變數設定說明.md](14-環境變數設定說明.md)。

### 3-1. Recall(派 bot 用)

```env
RECALL_API_URL="https://ap-northeast-1.recall.ai"   # region 要跟你申請 key 的 dashboard 一致
RECALL_API_KEY="你自己申請的 key"
```

### 3-2. Webhook(即時逐字稿)

```env
RECALL_WEBHOOK_URL="https://你在2-1領的固定網域.ngrok-free.dev"
RECALL_WEBHOOK_TOKEN="自訂一串隨機字元"
```

### 3-3. OpenAI(agent 模式的耳朵和嘴巴)

```env
OPENAI_API_KEY="sk-..."
```

agent 模式用它做即時轉錄 + 串流 TTS;就算不開 agent 模式,
舊路徑的語音回答(text→mp3)也靠它。**不填蜜塔就是啞巴**,只能聊天室文字回答。

### 3-4. Agent 模式總開關

```env
AGENT_MODE=on
```

`AGENT_PAGE_URL` **不用手動填**——`start.ps1` 啟動時會自動開 cloudflared quick tunnel,
抓到網址後寫回 `.env` 的這一行(每次啟動網址都會變,所以交給腳本)。

隨時想回退:`AGENT_MODE=off` 重啟,行為就跟舊版完全一樣(webhook + mp3 路徑)。

### 3-5. Gemini(插話/破冰的 LLM 額度)

```env
GEMINI_API_KEY="主帳號的 key"                  # aistudio.google.com/apikey 免費申請)
GEMINI_INTERJECTION_API_KEY="第二帳號的 key"   # 選填,建議設
```

`GEMINI_INTERJECTION_API_KEY` 是本分支新增的:插話決策**每輪講話都會打一次 LLM**,
是全系統最燒額度的呼叫;用第二個 Google 帳號的獨立額度隔離它,
燒完不會拖垮問答/摘要等其他功能。未設定時自動退回 `GEMINI_API_KEY`,功能照常。

> 模型不用改:第二帳號預設用 `gemini-flash-lite-latest`
> (新帳號申請的 key 用不了 `gemini-2.5-flash`,Google 對新用戶停開)。

## 4. 啟動與驗證

從專案根目錄:

```powershell
.\start.ps1
```

腳本會依序:Docker 基礎設施 → npm install → prisma db push →
**ngrok(webhook)** → **cloudflared(agent 網頁,並改寫 AGENT_PAGE_URL)** → 後端 + 前端。

啟動輸出要看到這兩行才算 agent 模式就緒:

```
ngrok started -> https://你的固定網域.ngrok-free.dev
cloudflared started -> AGENT_PAGE_URL=https://xxxx.trycloudflare.com/agent (written to backend\.env)
```

### 實際開會驗收

1. 前端建立會議、貼 Google Meet 連結,蜜塔進場
2. 開口說「**蜜塔**」→ **1.5 秒內**要聽到「我收到了」的確認語音(舊版是幾十秒~幾分鐘)
3. 接著問問題 → ack 之後開始查資料,答案開始播放不再等整支 mp3
4. 蜜塔講話時插話 → 0.5 秒內她會安靜讓路

## 5. 常見問題

| 症狀 | 原因與解法 |
|------|-----------|
| 啟動 log:`AGENT_MODE is not 'on' -> skipping cloudflared` | `.env` 的 `AGENT_MODE` 不是 `on`(第 3-4 節) |
| 啟動 log:`cloudflared not found` | 沒裝 cloudflared,或裝完沒開新 shell(第 2-2 節);此時自動退回舊路徑,不會壞,只是慢 |
| 啟動 log:`ngrok not found` / `RECALL_WEBHOOK_URL not set` | 第 2-1 / 3-2 節沒做完;沒有 webhook 就沒有即時逐字稿 |
| 喚醒有反應但蜜塔不出聲 | `OPENAI_API_KEY` 沒填(第 3-3 節) |
| Recall API 回 401 | key 跟 region 不一致:`RECALL_API_URL` 的 region 要跟申請 key 的 dashboard 相同 |
| 同一句「蜜塔」隔幾分鐘又被回答一次 | 不應發生——agent 模式下 webhook 的語音喚醒路徑會自動停用;遇到請帶 log 回報 |
| 改了 `.env` 沒效果 | 後端要重啟(Ctrl+C 再 `.\start.ps1`) |
| 插話功能一直失敗、額度爆掉 | 設第二把 key 隔離(第 3-5 節);注意插話預設是關的(`INTERJECTION_ENABLED=false`),要測才開 |

## 6. 這次改動不影響的部分(給心裡有數)

- **聊天室問答完全不受影響**:打字喚醒走 `participant_events.chat_message`,跟 STT 無關(詳見 16 文件第 06 節)
- **會後摘要、逐字稿照舊**:webhook 的 `transcript.data` 仍負責寫逐字稿
- **`AGENT_MODE=off` 隨時可回退**,舊路徑完整保留
