# 🟢 語音延遲修正(feature/bot-voice-latency-fix)環境設定

> 🟢 **活文件**:本分支合併後,組員要做的環境調整。
> 前提:你原本的環境已經跑得起來(Docker、`.env` 基本變數、ngrok 都已設定好)。
> 背景與架構說明見 [16-語音延遲根因分析報告.md](16-語音延遲根因分析報告.md),本文只講要動手的部分。

---

## 1. 這個分支整體加了什麼

| 改動 | 內容 | 你要做的事 |
|------|------|-----------|
| **Output Media 語音 agent(方案 A)** | bot 掛一個 agent 網頁當耳朵/嘴巴:網頁收會議音訊 → 後端 `/ws/agent` 即時轉錄(OpenAI)→ 喚醒後串流 TTS 回話。喚醒 ack 從分鐘級降到秒級 | 裝 cloudflared + `.env` 加 `AGENT_MODE=on`(第 2、3 節) |
| **start.ps1 自動開 agent tunnel** | 啟動時自動開 cloudflared quick tunnel,並把網址寫回 `.env` 的 `AGENT_PAGE_URL` | 不用做事,裝好 cloudflared 就會動 |
| 喚醒詞 regex 擴充 | 涵蓋 STT 常見誤轉(蜜塔→米塔等) | 不用做事 |
| 插話/破冰第二把 Gemini key | 選填,見第 5 節「額外建議」 | 選擇性 |

程式碼新增:`backend/src/agent/`(relay + registry)、`backend/src/routes/agent-page.ts`、
`frontend/src/app/agent/page.tsx`;沒有新的 npm 套件,拉完 code 不用重裝依賴。

---

## 2. 需要安裝:cloudflared(每人一次)

bot 的雲端瀏覽器要從外網開你本機的 agent 網頁,需要一條 tunnel。
不能共用 ngrok:免費網域對瀏覽器導覽會插 ERR_NGROK_6024 警告頁,bot 開不進去,
所以另外用 cloudflared(不用註冊帳號、不用任何設定)。

```powershell
winget install Cloudflare.cloudflared
```

裝完**開新的 PowerShell** 確認 `cloudflared --version` 有輸出即可。

---

## 3. `backend/.env` 要加的變數

```env
# Output Media 即時語音 agent(方案 A)
AGENT_MODE=on
AGENT_PAGE_URL="https://replaced-by-start-ps1.trycloudflare.com/agent"
```

- `AGENT_PAGE_URL` **不用手動填有效網址**:`start.ps1` 每次啟動會自動開 quick tunnel、抓網址、改寫這一行(quick tunnel 網址每次都變,所以交給腳本)。佔位字串照抄即可。
- 另外確認原本就有的 `OPENAI_API_KEY` 已設定——agent 模式的即時轉錄(STT)和串流 TTS 都靠它,沒有它 agent 模式起不來。
- 想回退隨時 `AGENT_MODE=off` 重啟,行為與舊版(webhook + mp3)完全一致。

改完 `.env` 要重啟後端才生效。

---

## 4. 啟動與驗證

照常 `.\start.ps1`,啟動輸出多看這一行:

```
cloudflared started -> AGENT_PAGE_URL=https://xxxx.trycloudflare.com/agent (written to backend\.env)
```

實際開會驗收:

1. 說「**蜜塔**」→ **1.5 秒內**聽到「我收到了」(舊版是幾十秒~幾分鐘)
2. 答案開始播放不再等整支 mp3
3. 蜜塔講話時插話 → 0.5 秒內讓路

| 症狀 | 解法 |
|------|------|
| log:`cloudflared not found` | 第 2 節沒裝,或裝完沒開新 shell。此時自動退回舊路徑,不會壞,只是慢 |
| log:`AGENT_MODE is not 'on' -> skipping cloudflared` | `.env` 沒加 `AGENT_MODE=on` |
| 喚醒有反應但不出聲 | `OPENAI_API_KEY` 沒設 |

---

## 5. 額外建議(選填):插話/破冰用第二把 Gemini key

插話決策每輪講話都會打一次 LLM,是全系統最燒免費額度的呼叫。本分支新增專用 key,
用第二個 Google 帳號的獨立額度隔離它,燒完不拖垮問答/摘要:

```env
GEMINI_INTERJECTION_API_KEY="第二個 Google 帳號申請的 key"   # aistudio.google.com/apikey
```

- 不設也完全沒事:自動退回 `GEMINI_API_KEY`,功能照常。
- 模型不用設:預設 `gemini-flash-lite-latest`(新帳號的 key 用不了 `gemini-2.5-flash`,Google 對新用戶停開)。
- 插話/破冰本身預設仍是關的(`INTERJECTION_ENABLED` / `ICEBREAKER_ENABLED`),要測才開。
