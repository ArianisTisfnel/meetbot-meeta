## 1. 這次改了什麼(對使用者可見的行為)

**蜜塔現在接得住「沒喊名字的追問」。** 以前每一句都得喊「蜜塔」,或是在她「只被叫名字」
之後的 8 秒內接話才行;現在她看得懂整段對話:

```
你:蜜塔,報名截止日是什麼時候
蜜塔:(回答)
你:那名額有限制嗎          ← 以前完全沒反應,現在會回答
你:那如果超過了會怎樣      ← 第三輪追問一樣接得住
```

代詞也算:剛問完她之後說「你可以再確認一次嗎」,她知道那個「你」是自己。

**不會亂接的情況**(這些都有離線劇本鎖住,不是靠祈禱):

- 對別人說話 —— 「小華你覺得這樣可以嗎」、「我覺得可以,你再看一下附件」→ 沉默
- 叫停之後 —— 說過「蜜塔 不用了」就關掉對話串,後面的討論不會把她喚回來
- 話題轉開 —— 有人喊了一聲「蜜塔」但接著大家聊別的 → 沉默
- 一整段正常討論 —— 完全沒提到她就完全不會送去判斷(連 LLM 都不會打)

**額度沒有變多。** 定址、意圖分類、插話決策原本是三次高度重疊的 LLM 呼叫,
現在合併成每輪一次,**呼叫數不增反減**。

---

## 2. 行為變化,測的時候心裡有底

| 情境 | 以前 | 現在 |
|------|------|------|
| 「蜜塔,X」句首呼喚 | 秒級 ack → 回答 | **一樣**,快速路徑沒動 |
| 只喊「蜜塔」→ 下一句問問題 | 8 秒內接得住 | 接得住,但**慢約 2.5 秒**(改成等整輪講完才判,見下) |
| 「那名額有限制嗎」這種追問 | 沒反應 | **會回答**,慢約 2.5 秒 |
| 她主動插話之後你追問 | 沒反應 | **仍然沒反應**(刻意留的缺口,見第 4 節) |

那 2.5 秒是 `INTERJECTION_TURN_SILENCE_MS`:追問要等你這一輪講完才判斷,
否則一句話被 STT 切成好幾段就會重複打 LLM。句首呼喚不受影響(它走純規則的快速路徑)。

---

## 3. 怎麼確認你拉到的是新版

重啟後端,開一場會,問一題再追問一句。後端 log 應該出現:

```
addressing: follow-up in open thread, dispatching
```

沒出現的話,先確認 `INTERJECTION_ENABLED=true`(追問的判斷掛在插話引擎的 turn 結束時機上,
這個關掉的話追問也會跟著失效)。

---

## 4. 已知缺口(不是 bug,是刻意沒做)

**蜜塔主動插話之後,對話串不會打開。** 所以「她插話補充 → 你接著追問」目前接不上,
要重新喊一次名字。沒做的理由是成本:插話後 90 秒內每一輪都會多一次 LLM 呼叫。
測的時候遇到請不用回報,但**如果你覺得這個情境很常發生,請說**——那會改變我們的取捨。
