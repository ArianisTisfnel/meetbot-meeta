# 23 — 行事曆功能環境設定

> 🔒 **凍結快照**：記錄 `feat/calendar-ui` 併入當下需要動手做的事。讀完即退場，不必回頭維護。
> 沒有列到的項目 = **不用做**。

拉到這份 code 之後，依序照做。全部大約 5 分鐘。

---

## 一、要不要 `npm install`？

**不用。** 這次沒有新增任何套件。

行事曆的日期計算、共同空檔演算法、Google Calendar 呼叫全部用原生 `Date` 與 `fetch` 寫成，
刻意不引入 date-fns／luxon／googleapis。

---

## 二、要不要 `npx prisma db push`？

**要，一定要跑。** 不跑的話後端一啟動就會因為找不到資料表而報錯。

```bash
cd backend && npx prisma db push
```

> ⚠️ 如果後端正在跑，`db push` 後面接的 `prisma generate` 會因為 DLL 被鎖住而失敗
> （`EPERM ... query_engine-windows.dll.node`）。**先把後端關掉**再跑，或跑完再單獨執行
> `npx prisma generate`。

新增的東西（純新增，不會動到既有資料）：

| 項目 | 說明 |
|------|------|
| `meeting_instances` 加 4 欄 | `scheduled_start_at` / `scheduled_end_at` / `timezone` / `gcal_event_id` |
| `meeting_status` 加 2 個值 | `SCHEDULED`（已排定，蜜塔還沒進去）、`CANCELED`（這場會不開了） |
| 新表 `meeting_attendees` | 與會者與 RSVP 出席回覆 |
| 新表 `calendar_connections` | 各人的 Google Calendar 授權 |
| 新表 `busy_blocks` | 從 Google Calendar 匯入的忙碌時段快取 |

---

## 三、要不要加環境變數？

**要，加在 `backend/.env`。** 值跟 `frontend/.env.local` 裡的**同一組**，直接複製過去即可。

```env
GOOGLE_CLIENT_ID="（與 frontend/.env.local 同值）"
GOOGLE_CLIENT_SECRET="（與 frontend/.env.local 同值）"
```

**為什麼後端也要一份**：背景同步忙碌時段是在使用者離線時跑的，後端得自己用 refresh token
去換 access token。前端 NextAuth 的 token 只有瀏覽器開著才拿得到。

**不設會怎樣**：行事曆照樣能用，只是 Google 同步整個停用——疊圖只看得到本系統的會議，
所有成員都顯示「未同步」。畫面上會明說是後端沒設定，不會假裝在運作。

### 選填（有預設值，不設也可以）

| 變數 | 預設 | 作用 |
|------|------|------|
| `CALENDAR_SYNC_DAYS_AHEAD` | `35` | 忙碌時段往後同步幾天 |
| `CALENDAR_SYNC_INTERVAL_MINUTES` | `15` | 背景同步間隔；設 `0` 只留手動同步 |

---

## 四、要不要在 Google Cloud Console 改設定？

**要，加一個 scope。** 到你們的 OAuth 同意畫面，把這個加進已核准的範圍：

```
https://www.googleapis.com/auth/calendar.freebusy
```

原本就有的 `calendar.events` 保留不動。

**為什麼是 freebusy 而不是 calendar.readonly**：`freebusy` 只回「幾點到幾點忙」，
拿不到行程標題與內容。疊圖和找空檔只需要這個，是能滿足需求的最小權限。

---

## 五、每個人都要重新登入一次

**一定要。** 登出再登入，會看到 Google 的同意畫面多要兩項權限。

**為什麼**：Google 只在使用者「重新同意授權」時才發 refresh token。沒有它，後端無法在你
離線時同步忙碌時段。舊的 session 帶的是舊 scope，不重新登入就永遠拿不到。

> 順帶一提：現在**每次登入都會出現同意畫面**（`prompt=consent`）。這是刻意的——
> 不強制的話，換一台裝置登入就再也拿不到 refresh token，背景同步會無聲失效，
> 而且完全沒有錯誤訊息可查。覺得太吵可以改，作法寫在 `frontend/src/lib/auth.ts` 的註解裡。

登入後進「行事曆」，左欄的 **Google Calendar** 卡片應該顯示「已連結」。
沒有的話按「立即同步」看錯誤訊息。

---

## 六、不用做的事

明確列出來，免得你們自己猜：

- ❌ **不用**裝 cloudflared / ngrok。行事曆同步是後端主動去拉 Google，不需要對外可達的網址。
- ❌ **不用**改 `start.ps1`。
- ❌ **不用**動 Recall、Dify、MinIO 的任何設定。
- ❌ **不用**手動建立資料表或跑 SQL。`db push` 就夠了。
- ❌ **不用**重新上傳素材或重建知識庫。

---

## 七、驗收：怎麼確認弄好了

1. 後端啟動時的 log 應該有一行：
   ```
   Calendar sync poller started (every 15m)
   ```
   如果看到「未啟動：未設定 GOOGLE_CLIENT_ID／GOOGLE_CLIENT_SECRET」→ 回到第三步。

2. 登入後進任一專案 → **行事曆** 分頁，左欄 Google Calendar 卡片顯示「已連結」。

3. 按「+ 排定會議」排一場，應該：
   - 立刻出現在週曆格線上
   - 出現在你自己的 Google 日曆裡（Google 會寄邀請信給與會者）
   - 取消該會議後，Google 日曆上那筆也跟著消失

4. 你 Google 日曆上原有的行程，會以你的顏色出現在成員疊圖上（可能要按一次「立即同步」）。

## 八、已知限制

- **時區用固定偏移量，不是 IANA 時區**。台灣沒有日光節約時間所以完全正確；
  有 DST 的地區在切換那一週會偏一小時。要修的話只需換掉 `backend/src/lib/free-slots.ts`
  的 `dayWindows()` 一個函式。
- **refresh token 目前明文存在 DB**。本機／自架資料庫的開發階段取捨，上線前要加一層加密。
- **忙碌時段用輪詢而非 Google 推播**，所以別人剛加的行程最久 15 分鐘後才會出現在疊圖上。
  等不及就按「立即同步」。
- **通知／提醒發送（spec §4.5）還沒做**。RSVP 可以回覆，但「催未回覆」的自動寄信還沒接上。
