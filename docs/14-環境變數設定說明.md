# 🟢 環境變數設定說明

> 🟢 **活文件**:須與 `backend/src/types/env.ts` 同步。若與程式不符,以程式為準並回寫本文件。
>
> 最後更新:2026-07-15

後端變數定義與驗證都在 `backend/src/types/env.ts`(zod schema,啟動時驗證,缺必填會直接 exit)。
範本:`backend/.env.example`。前端變數在 `frontend/.env.local`。

**改完 .env 一律要重啟才生效**(dev 模式沒有 watch)。

---

## 1. 後端 `backend/.env`

### 1-1. 資料庫(Supabase)

| 變數 | 必填 | 說明 |
|------|:---:|------|
| `DATABASE_URL` | ✅ | **App 執行期**連線。用 port **6543**(transaction pooler,`?pgbouncer=true&connection_limit=5`)——避免 session-mode 連線數上限(15)被 Vexa 與 meetbot 佔滿 |
| `DIRECT_URL` | ✅ | **Prisma CLI 專用**(`db execute` / `migrate` / `db pull`)。用 port **5432**(session pooler)。⚠️ transaction pooler 跑 DDL 會被 pgbouncer 斷線(P1017),所以 CLI 必須走這條 |
| `SUPABASE_URL` | ✅ | 專案 URL(`https://<proj>.supabase.co`) |
| `SUPABASE_SERVICE_ROLE_KEY` | ✅ | Service role key(Storage 上傳用,勿外流) |
| `SUPABASE_STORAGE_BUCKET` | ✅ | 逐字稿/上傳檔的 bucket,目前用 `meeting-materials` |

### 1-2. Dify(RAG 與摘要)

| 變數 | 必填 | 說明 |
|------|:---:|------|
| `DIFY_API_BASE` | ✅ | `https://api.dify.ai/v1` |
| `DIFY_DATASET_API_KEY` | ✅ | `dataset-` 開頭。建知識庫、上傳文件、查索引、抓 segments(摘要卡)用 |
| `DIFY_WORKFLOW_API_KEY` | ✅ | `app-` 開頭。**問答 Chatflow** 用 |
| `DIFY_SUMMARY_WORKFLOW_API_KEY` | ✅ | `app-` 開頭(歷史保留) |
| `DIFY_MEETING_SUMMARY_WORKFLOW_API_KEY` | ✅ | `app-` 開頭。**會議摘要 workflow** 用 |
| `DIFY_CHATFLOW_TIMEOUT_MS` | | 問答逾時,預設 `45000` |

> ⚠️ 兩種 key 完全不同,用錯會 401。另外 **Dify 平台端**的 Chatflow 環境變數裡也要設一份 dataset key——沒設的話 RAG 會「靜默失效」:不報錯,但所有問題都回「沒有檢索到相關資訊」(backend log 會出現 no-result sentinel 警告)。

### 1-3. LLM(分類、閒聊、插話決策、破冰、逐字稿 QA)

| 變數 | 必填 | 說明 |
|------|:---:|------|
| `ANTHROPIC_API_KEY` | ✅ | Claude。`GEMINI_API_KEY` 未設時的預設 provider(短輸出 Haiku、長輸出 Sonnet,需儲值) |
| `GEMINI_API_KEY` | | **設了就整批改走 Gemini**(AI Studio 免費額度,[aistudio.google.com/apikey](https://aistudio.google.com/apikey))。想換回 Claude 就把這行註解掉重啟 |
| `GEMINI_MODEL` | | 預設 `gemini-2.5-flash`(推論時關閉 thinking 求快) |
| `GEMINI_INTERJECTION_API_KEY` | | 插話/破冰**專用**的第二把 Gemini key(另一個帳號的免費額度)。插話決策每輪講話都會打 LLM、最燒額度,用獨立帳號隔離,燒完不拖垮其他功能。未設定時退回 `GEMINI_API_KEY` |
| `GEMINI_INTERJECTION_MODEL` | | 預設 `gemini-flash-lite-latest`(新帳號不能用 `gemini-2.5-flash`,對新用戶停開) |

### 1-4. Bot Provider(進會議)

| 變數 | 必填 | 說明 |
|------|:---:|------|
| `BOT_PRIMARY_PROVIDER` | | `recall`(預設)或 `vexa`;另一個自動成為 failover 備援。Vexa 進 Meet 實測被 reCAPTCHA 擋,2026-07 起以 Recall 為主 |
| `VEXA_API_URL` / `VEXA_WS_URL` | ✅ | 自架 Vexa(本機 `http://localhost:8056` / `ws://localhost:8056`) |
| `RECALL_API_URL` | | Region URL,例 `https://ap-northeast-1.recall.ai`。未設 → 只用 Vexa、無 failover |
| `RECALL_API_KEY` | | Recall API key |
| `BOT_ADMISSION_TIMEOUT_MS` | | Vexa 進場逾時,預設 `30000` |
| `RECALL_ADMISSION_TIMEOUT_MS` | | Recall 進場逾時,預設 `90000`(Recall 進場本身就要 ~30 秒,別調太短) |
| `RECALL_TRANSCRIBE_LANGUAGE` | | 轉錄語言,預設 `auto`(可中英夾雜,中文會議建議)。`multi` 不是合法值 |
| `OPENAI_API_KEY` | | Recall bot 說話用的 TTS(text→mp3)。**未設定時 Recall bot 不能語音回答**,只能聊天文字回答 |

### 1-5. Recall 即時 Webhook(即時喚醒問答的前提)

| 變數 | 必填 | 說明 |
|------|:---:|------|
| `RECALL_WEBHOOK_URL` | | 公開可達的 base URL(本機開發用 ngrok tunnel)。**未設定 → 沒有即時逐字稿**,Recall 退回 meeting_captions:只有會後逐字稿、喚醒詞問答整個不會動 |
| `RECALL_WEBHOOK_TOKEN` | | 自訂隨機字串,驗證 POST 來源(`?token=`) |

### 1-6. 主動插話(interjection)— 🧪 測試階段

| 變數 | 預設 | 說明 |
|------|------|------|
| `INTERJECTION_ENABLED` | `false` | 總開關。目前**關閉** |
| `INTERJECTION_TURN_DETECTOR` | `silence` | 時機層:`silence`=純停頓計時;`livekit`=LiveKit turn-detector 語意判斷(**首次啟用下載 ~150MB 模型**到 `backend/models/`) |
| `INTERJECTION_TURN_SILENCE_MS` | `2500` | 停頓多久視為一輪話結束 |
| `INTERJECTION_EOU_CHECK_MS` | `1000` | livekit 模式:靜默多久先問 EOU 模型 |
| `INTERJECTION_EOU_LANGUAGE` | `zh` | EOU 閾值查表語言碼 |
| `INTERJECTION_EOU_THRESHOLD` | `0.1` | EOU 閾值(實測講完 ≥0.68、沒講完 ≤0.008,0.1 是保守值) |
| `INTERJECTION_COOLDOWN_MS` | `90000` | 兩次插話最小間隔,防話癆 |

### 1-7. 沉默破冰(icebreaker)— 🧪 測試階段

| 變數 | 預設 | 說明 |
|------|------|------|
| `ICEBREAKER_ENABLED` | `false` | 總開關。目前**關閉** |
| `ICEBREAKER_SILENCE_MS` | `40000` | 全場靜默多久觸發 |
| `ICEBREAKER_COOLDOWN_MS` | `300000` | 冷卻 5 分鐘 |

### 1-7b. 回覆功能標籤(reply tags)

| 變數 | 預設 | 說明 |
|------|------|------|
| `REPLY_TAGS` | `on` | 蜜塔的**聊天室**訊息前加【資料檢索】【會議記錄】【閒聊】【冷場插話】【破冰】等功能標籤，讓每則回覆可歸因到觸發它的子系統。設 `off` 完全不顯示（正式對外會議用）。**語音永遠不唸標籤**，不受此開關影響 |

> 標籤只前綴在送進會議聊天室的那一份；chatLog、插話對話窗、會後逐字稿與摘要一律存原文，
> 避免污染 LLM 輸入。詳見 `docs/18-使用回報/2026-07-28-01-處理結果.md`。

### 1-8. Server 與寄信

| 變數 | 預設 | 說明 |
|------|------|------|
| `APP_PORT` | `4000` | 後端 port |
| `APP_CORS_ORIGINS` | `http://localhost:3000` | 逗號分隔 |
| `APP_BASE_URL` | `http://localhost:3000` | 組邀請接受連結用 |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_SECURE` / `MAIL_FROM` | (皆選填) | 邀請信 SMTP。**未設定 = 不寄信但功能照常**(連結印在 log、UI 可複製)。Gmail 作法:開兩步驟驗證 → [產生應用程式密碼](https://myaccount.google.com/apppasswords)(16 碼去空格)填 `SMTP_PASS` |
| `INVITATION_TTL_DAYS` | `7` | 邀請連結效期 |

## 3. 常見情境速查

| 我想要… | 要動的變數 |
|---------|-----------|
| 換 LLM 供應商(Gemini ↔ Claude) | 設定/註解 `GEMINI_API_KEY`,重啟 |
| 開插話功能來測 | `INTERJECTION_ENABLED=true`(建議同時 `INTERJECTION_TURN_DETECTOR=livekit`) |
| 開破冰功能來測 | `ICEBREAKER_ENABLED=true` |
| 讓 Recall bot 開口說話 | 設 `OPENAI_API_KEY` |
| 讓喚醒詞「即時」有反應 | 設 `RECALL_WEBHOOK_URL` + `RECALL_WEBHOOK_TOKEN`(本機要 ngrok) |
| 跑 Prisma CLI(migrate / db execute) | 確認 `DIRECT_URL`(5432)存在,CLI 自動走它 |
| 真的把邀請信寄出去 | 填 SMTP 六個變數 |

## 4. 除錯對照

| 症狀 | 先查 |
|------|------|
| 後端啟動直接 exit + `Invalid environment variables` | 訊息會列出缺哪些必填變數 |
| Dify 回 401 | dataset key 與 app key 用反了(1-2 的警告) |
| 每題都回「沒有檢索到相關資訊」 | Dify **平台端**環境變數沒設 dataset key(靜默失效) |
| Prisma CLI 報 P1017(connection closed) | CLI 走到 6543 了;確認 `DIRECT_URL` 存在且是 5432 |
| 蜜塔不說話只回聊天室 | `OPENAI_API_KEY` 沒設(Recall TTS) |
| 喚醒詞完全沒反應 | `RECALL_WEBHOOK_URL` 沒設或 ngrok 斷了 |
